# Project Guide

## Overview

This repository contains a single-page portfolio built with the Next.js App Router. The root layout provides the navigation, footer, theme provider, translation provider, and smooth-scroll wrapper. The home route composes the hero, technology marquee, about, projects, experience, and awards sections. The footer contains the contact links and resume download.

## Source Layout

| Path | Responsibility |
| --- | --- |
| `src/app/page.tsx` | Home page and section order. |
| `src/app/layout.tsx` | Global layout, fonts, metadata, theme and translation providers. |
| `src/app/globals.css` | Tailwind import, theme colors, typography and custom utilities. |
| `src/components/sections/` | Hero, about, projects, experience, awards, contact and technology marquee sections. |
| `src/components/layout/` | Navbar, footer and smooth-scroll wrapper. |
| `src/components/ui/` | Small reusable UI helpers, including the magnetic interaction wrapper. |
| `src/providers/I18nProvider.tsx` | English/French state and nested message lookup. |
| `src/messages/en.json` | English interface and portfolio copy. |
| `src/messages/fr.json` | French interface and portfolio copy. |
| `src/app/sitemap.ts` | Search-engine sitemap for the canonical home page. |
| `src/app/robots.ts` | Crawler access rules and sitemap location. |
| `src/lib/utils.ts` | Shared utility functions. |
| `public/` | Images, icons and downloadable assets served from the site root. |

## Editing Portfolio Content

- **Translated copy:** Update the corresponding nested keys in both `src/messages/en.json` and `src/messages/fr.json`. Components access values through `useI18n()` and keys such as `about.content`.
- **Projects:** Edit the project records near the top of `src/components/sections/Projects.tsx`. Project title, category, image path, external links and technology tags are currently component data; the section heading and view label are translated.
- **Experience:** The three experience entries are assembled in `src/components/sections/Experience.tsx`, with their text supplied by matching message keys in both language files.
- **Awards:** Award titles, issuers and categories are defined in `src/components/sections/Awards.tsx`; descriptions and the section heading come from the message files.
- **About details:** The about paragraph and heading are translated. The skill labels in `src/components/sections/About.tsx` are currently static.
- **Navigation and contact links:** Update the link list and destinations in `src/components/layout/Navbar.tsx` and `src/components/layout/Footer.tsx`. The footer's contact anchor is `#contact`.

Keep the English and French message files in sync by preserving the same nested key structure. Messages are imported statically so server-rendered HTML includes real copy before hydration. The provider uses dot-separated keys and returns the key itself when a translation is unavailable.

## Static Assets and Metadata

Place site assets in `public/` and reference them from components with root-relative paths, for example `/iChef.avif`. The About section uses `/me.jpg`; project imagery and the resume download are also served from `public/`.

Page title, description, canonical URL, social metadata, metadata base URL, and favicon paths are configured in `src/app/layout.tsx`. The home page also emits `Person` JSON-LD structured data. Update these alongside `src/app/sitemap.ts` and `src/app/robots.ts` if the public domain changes. The resume link expects `public/resume.pdf`.

## UI and Theme

The project uses Tailwind CSS 4 utilities. Shared colors and font aliases are defined in `src/app/globals.css`; Google font variables and global theme providers are set up in `src/app/layout.tsx`. The navbar toggles English/French and light/dark modes. Motion effects use Framer Motion, and smooth scrolling is provided by React Lenis.

## Local Development and Release Checks

Use Node.js and npm, then run:

```bash
npm ci
npm run dev
```

Before a release, run the available checks:

```bash
npm run lint
npm run build
npm run start
```

`npm run start` serves the production build, so run it after a successful build. There is no automated test command configured at present.

## Deployment

Deploy as a standard Next.js application on Vercel or another compatible hosting service. Use the production build output generated by `npm run build`; keep public assets and the resume file in the `public/` directory so they are included in the deployment.
